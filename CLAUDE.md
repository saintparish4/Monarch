# Monarch

An ERC-4337 v0.8 paymaster that lets a consumer app pay its users' gas, built
with Solidity and Foundry. Scripts run through npm: `npm run build`, `test`,
`lint`, `fmt:check`, `snapshot:check`, `analyze`.

## Commit and PR message format

Universal format, applied to every project. Subject line is Conventional
Commits — `type(scope): one-liner`, imperative mood, lowercase after the colon,
no trailing period, whole line <= 72 characters. Types: `feat`, `fix`, `perf`,
`refactor`, `docs`, `test`, `chore`, `build`, `ci`. Scope is the area touched —
in this repo: `paymaster`, `account`, `libs`, `script`, `detector`, `demo`,
`deploy`, `docs`, `ci`.

The full template below is the **PR body**, and the **squash/merge commit**
message that lands on `master`. Intermediate commits on a branch carry the
subject plus `## Background` and `## Summary` only — Validation, Checklist and
Related Issues describe the change as a whole, and are only true once the
branch is complete.

```
type(scope): one-liner description

## Background

Short paragraph on what is going on and why this change exists — the state
before, and what it could not do.

## Summary

- Informative, concise bullets. What changed, in terms a reviewer can check
  against the diff. No over-explaining.

## End-to-End Verification

Short paragraph on how verification was actually achieved — what was run,
against what, with what result. State plainly when something is an
integration check rather than a proof.

## Validation

- `npm run build`, `npm test` pass
- `npm run lint`, `npm run fmt:check` pass
- `npm run snapshot:check` passes (or: gas snapshot updated, deltas listed)
- `npm run analyze` (slither) clean, including the ERC-7562 detector

## Checklist

- [x] All commits are signed (PRs with unsigned commits cannot be merged)
- [x] Tests have been added / updated
- [x] Documentation has been added / updated
- [x] I have reviewed this pull request (self-review)

## Related Issues

- Closes #123
```

Rules for filling it in:

- Adapt the section contents to the project; never adapt the section names or
  their order.
- Every Validation bullet must name a command that was actually run. An
  unrun check is omitted, not listed optimistically.
- Every Checklist box is `[x]` or `[ ]` honestly. A `[ ]` with a one-line
  reason beats a false `[x]`.
- Drop `## Related Issues` entirely when there is nothing to relate. Every
  other section is mandatory.
- Omit issue numbers from the subject line; GitHub appends `(#N)` itself on
  squash merge.
- No attribution trailers or footers, anywhere: commit messages, pull
  request bodies, and GitHub comments, reviews and review replies. Each
  ends at its last line of content — no `Co-Authored-By:`, no
  `Claude-Session:`, no `Generated with` or `Generated by` footer, no
  tool badge, emoji sign-off or horizontal-rule sign-off. Any tooling
  that would append such a line is overridden here.

### Markdown headings survive only on the `-F` path

Git's default cleanup strips lines beginning with `#` whenever the message is
edited, which silently deletes every `##` heading in this template. Verified:
`git commit -F msg.txt` keeps them; anything that opens the editor
(`git commit` bare, `git commit --amend` without `-F`, `-e`) does not.

Write the message to a file and commit with `git commit -F <file>`. As a
one-time safeguard, make the headings survive the editor path too:

```sh
git config core.commentChar ";"   # or: git config commit.cleanup verbatim
```

## Authorship

Commits carry the repository owner's identity, matching the existing history:

```sh
git config user.name "Sharif Parish"
git config user.email "saintparish6@gmail.com"
```

No second author is recorded on a commit for any reason. Whoever reviews and
pushes the change owns it.

## Signing

`commit.gpgsign=true` with SSH signing is expected. Unsigned commits cannot be
merged, so verify before claiming the checklist box — but verify the right
thing. `git log --show-signature` prints `No signature` whenever
`gpg.ssh.allowedSignersFile` is unset, even on a correctly signed commit,
because it cannot establish trust. The signature's presence is a property of
the commit object:

```sh
git cat-file commit HEAD | grep -q '^gpgsig' && echo signed || echo unsigned
```
